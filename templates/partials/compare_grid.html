{% load i18n %} {% comment %} The read-only multi-player comparison grid used by availability_compare.html. Always exactly 7 columns (Mon-Sun), unlike the single-user week-specific grid's real-dated 7-or-8 columns (partials/availability_grid.html) -- comparing several players' possibly different timezones works only as one shared abstract week shape, even though (since this page dropped its own General mode) every column DOES carry a real calendar date drawn from one specific real week, in the viewer's local time. Cells are plain divs, not buttons: nothing here is editable, the interactive behaviour (heat colouring, hover/tap detail) is entirely client-side JS keyed off data-day/data-hour (derived into an hour-of-week by availability_compare.html's own script). Parameters: columns [{'day_label', 'header_label', 'header_sublabel', 'header_title', 'iso_date'}, ...], one per column, in order -- pre-assembled server-side because Django templates cannot index `days` by another loop's counter to look up a matching date (the same reason partials/availability_grid.html pre-assembles its own cells). `day_label` (full weekday name) drives data-label, the text the hover tooltip/click-detail panel show; `header_label` (abbreviated weekday) plus `header_sublabel` (date) drive the two-line dated header, matching the single-user week-specific grid's own header exactly (avail-day-header--dated, partials/availability_grid.html). `iso_date` is None in General mode and a real local calendar date string in week-specific mode -- when present, each cell in that column carries a data-date attribute so the click/hover detail can show an exact date instead of just a day name. hours hour_labels() -> (hour, short_label, long_label) triples. hour_rows OPTIONAL -- week-specific mode only, None in General mode (falls back to one ordinary cell per (column, hour), matching this partial's original unconditional shape). One entry per hour_labels() row: (hour, short_label, long_label, cells), `cells` having exactly 7 entries (column order), each a `(column, tokens)` PAIR -- `column` is the matching entry from `columns` (pre-zipped server-side, since Django templates cannot zip two lists together) and `tokens` is a list of 0, 1, or 2 `data-how` TOKEN strings (see services.availability.utc_instant_token) for that (day, hour) position -- 0 -> a DST spring-forward gap (disabled, not tappable), 1 -> an ordinary cell, 2 -> a DST fall-back night's repeated local hour (two independently free-or-not real instants sharing this grid position, rendered as two half-width cells -- see services.availability. local_week_cell_shape for why the shape can hold 0/1/2 real hours per local slot, same reasoning as the single-user week-specific grid's week_grid_cells). {% endcomment %}
